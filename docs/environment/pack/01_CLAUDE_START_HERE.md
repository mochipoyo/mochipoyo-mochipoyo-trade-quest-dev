# Claude Codeへの実装指示

あなたは、このリポジトリの環境アーティスト兼Three.js実装担当として作業する。目的は、どの町・城・ダンジョンも似た間取りと質感になる現状を改善し、探索だけで地域と文化を見分けられる3Dの世界にすること。提案文だけで終わらせず、実装・素材接続・ビルド・動作検証まで進める。

## 対象と前提

- 対象：`mochipoyo/mochipoyo-mochipoyo-trade-quest-dev` の `feature/3d-full`。
- この資料の確認コミット：`62900a3d3df0f50fa9fe32e2fe7e119eea89e960`。現在のHEADが進んでいれば最新を優先して差分を確認。資料の古いコードで巻き戻さない。
- 既存はThree.js 0.186.1・Vite 8.3.4（取得したpackage.json）。この作業のためのUnreal移植や依存の一括更新はしない。
- キャラクターは現在の探索用3Dモデルを維持。人物をイラストの板や2Dスプライトへ戻さない。
- 参考画像の「建築の差、奥行き、材質、光、空間の展開」を採り入れ、既存作品のマップ・紋章・UIをコピーしない。
- `FFレゾナンス`の正式作品名は本資料では特定していない。想像で仕様を補完せず添付画像を優先する。

## 必須の成果

1. mapIdで確実に解決する個別の環境プロファイル。未登録IDを黙って汎用の草原へ落とさず、開発時に検出する。
2. 25の町で街路と地区構成、建物のシルエット、屋根、中心となる目印を個別化する。
3. 城・王宮は列柱、回廊、庭園、階段、玉座、地下の用途を区別。灰色の箱を巨大化するだけで終えない。
4. ダンジョンは狭い入口→主空間→分岐→見せ場などの空間変化を作る。自然洞窟に人工建築の同じ直角の間取りを流用しない。
5. 屋内167件は地域×用途×生活背景で作り分ける。宿の受付・食堂・寝室、武器店の展示・作業場、住宅の仕事場・生活空間を分ける。
6. フィールド12件は地域固有の地形シルエット、植生、岸辺、道路、遠景と入口ランドマークを作る。
7. 配置変更と同時に当たり判定、ワープ、NPC、宝箱、イベント、隠し通路、ミニマップを整合させる。
8. PC高画質とスマホ低負荷で同じゲーム内容を遊べる。低負荷時も主要な建築形状や目印は残す。

## 実施順序

### A：監査と安全な作業基盤

- 作業中の変更を保持して専用ブランチを作る。リポジトリの指示を読む。
- 最新の全MAP_DEFSを読み込んだ後で再抽出し、330件という数とID差分を確認。新規IDは追加し、削除されたIDは記録する。
- `GameMap`だけでなく、`expand-a*`, `tweaks68`, `Search`, `BossSymbol`, `QuizSymbol`, `World`, `Nav`, `EdgeExit`, `DungeonExit`, `Vehicle` の動的な座標参照を調べる。
- 既存の全マップのスナップショット、ワープグラフ、基準スクリーンショットを保存。
- 高品質化の有効・無効を切り替えられる開発用フラグを設ける。旧表示へ戻せる状態で進める。

### B：5地点で実装基準を作る

`poyo_village`, `rivel_castle`, `iron_mine_1`, `node_city`, `tradia` を、FLAGSHIP_SCENESに沿って実際に作り込む。

各地点につき、床・壁・屋根・固有の目印・光・間取り・当たり判定・イベント到達性・カメラ遮蔽・スマホ画質を一体で完成させる。1地点の完成を全体の完成と報告しない。

既存の表示にEnvironmentLayerを重ねるだけでは不足する。補助レイヤーは接続例として使い、地形・建物・屋内のbuilder本体とデータを変更して空間を作り直す。不要になった旧メッシュは非表示/生成抑止して重ねない。

### C：全地域と全マップへ展開

- 25町→主要な城/ダンジョン→残りのダンジョン→屋内→12フィールドの遠景を並行した制作単位に分けてもよいが、必要なエンジン改修は共通化する。
- 毎回同じモデルを同じ向きに並べて色だけ変える実装は不可。材質、形状、床割り、照明、道の構成、目印のうち最低3つを変える。
- `data/production_backlog.json` の状態を実績に応じて更新し、generated/design/integrated/verifiedを混同しない。
- 完了した単位を記録して継続。作業時間やコンテキスト制約があれば未完了リストと次の作業をファイルへ保存する。基盤だけで全件完了としない。

### D：品質検証とビルド

- パックの補助テストに加え、リポジトリの既存テストを実行。パックのテスト合格はゲーム統合合格を意味しない。
- 入口/出口往復、必須NPC会話、宝箱、階段、ボス戦後、脱出、再訪、旧セーブ復元、進行条件の前後を確認。
- `three-src` のビルドを行い、公開に必要な `3d/` と静的アセットの出力まで確認。
- PR/報告には同じ座標・同じカメラのbefore/after、実測環境、フレーム時間、ロード時間、変更したマップ数、未完了数を示す。

## 禁止する完了の扱い

- コンセプト画像を貼っただけで3D世界が完成したと言わない。
- normalMapやAOがないのにPBR一式完成と書かない。
- シェーダーの色替え、小物の自動散布、Bloom強化だけでリデザイン完了としない。
- 未確認のFPSやスマホ動作を推定値で合格にしない。
- 到達性のために鍵・ボス・進行条件を削除しない。
- 2D版や戦闘を巻き込むレイアウト変更は、両版の座標整合または明示した3D専用オーバーレイで扱い、片側だけ壊さない。

不明な日常的実装判断はリポジトリを調べて解決する。ユーザーへの都度確認で作業を止めず、取り消せる変更は進める。ゲーム全体に影響する未解決の仕様だけを、具体的な差分と影響とともに提示する。
