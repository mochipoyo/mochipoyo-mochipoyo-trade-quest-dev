# 環境リデザイン：監査（段階 A）

## 1. マップの論理はどこで決まるか（3D版だけ座標をずらさないための確認）

- マップの論理（タイル `rows`・ワープ・NPC・宝箱・イベント・建物）は2D版と3D版が共通で使う `MAP_DEFS`（`js/data/*.js`）。3D版（`three-src/`）は読み込み済みの `GameMap` から形を作るだけで、座標を独自に持たない。
- 読み込みの後でタイルを書き換えるスクリプト（読み込み順に適用）：`js/data/towns.js`・`world.js`・`expand-a*.js`・`expand72-towns.js`・`remake71-poyo.js`・`js/rpg/mapremake.js`、そして今回の `js/data/env76.js`。`js/rpg/masters.js` はタイルを読むだけ（師匠の置き場所の判定）、`js/core/map.js` は建物の足元をタイルに写す。
- 固定の座標を持つもの：ワープの行き先（`tx`・`ty`。データの38ファイル）、物語の `enterMap(...)`（4ファイル）、イベント・NPC の位置（各マップのデータ）。今回はどれも動かしていない。
- 動的に変わるもの：`showIf` の建物（例：演算都市ノードの自由市場。フラグで地図を作り直す＝`GameMap.buildingKey`）、`showIf`／`hideIf`／`showWhen` の NPC。3D版はフラグが変わると地図ごと組み立て直すので、レシピもその時点のフラグで作る（ノードの改革前後）。

## 2. 論理を変えたのは2マップだけ（js/data/env76.js）

| マップ | 変更 | 理由 |
|---|---|---|
| rivel_castle | 10マス `:`（床）→ `I`（柱） | 絨毯の両側の列柱を、3D の飾りではなく当たり判定のある柱にする（柱の間は1マスおきに通れる） |
| poyo_village | 4マス `.` → `f`（木） | 中央の緑地の村の大樹（2×2）。3D は1本の大樹と石囲い |

- 書き換えは「いまの文字が期待どおり」かつ「NPC・宝箱・ワープ・イベントのマスでない」ときだけ（違えば書き換えず `ENV76.skipped` に記録）。
- 確認（`docs/tools/env/logic_snapshot.js`・`reach_check.js`）：597マップのうちタイルが変わったのはこの2マップの14マスだけ。ワープ・NPC・宝箱・イベント・建物の位置は全マップで同じ、ワープのつながりも同じ。入口から行けるマスは、柱・木にしたマスの分だけ減り（603→593・1810→1806）、話せる人・宝箱・イベント・ワープに行けなくなった所は0。

## 3. プロファイル（マップIDの対応）

- パックは330マップ、いまのゲームは597マップ（`docs/environment/ID_DIFF.md`）。いまのデータを正として、全597マップのプロファイルを `three-src/public/environment-v1/data/profiles.json` に作った（パックの330件＋足りない267件は、親の町・建物の種類・地域から作った derived）。
- 未登録のマップIDは、実行時に警告を1回出して `Env.missing` に記録する（汎用に黙って落とさない）。`logic_snapshot.js` は「ゲームの全マップIDにプロファイルがあるか」を確かめる（未登録0）。

## 4. 切り替え（元に戻せる）

- localStorage `mtq3d-env`＝`v1`（既定）／`off`（従来の表示）。URL の `?env=off|v1` でも同じ。`off` では、レシピもプロファイルの読み込みも行わない。
- レシピの準備・組み立てで失敗したマップは、その回はレシピなしで組み立て直す（`Env.errors` に記録）。
