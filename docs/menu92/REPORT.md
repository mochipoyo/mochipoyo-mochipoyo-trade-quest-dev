## 1. ご指摘と対応

| ご指摘 | 対応 |
|---|---|
| パーティメンバーの装備を選んでいるときに、他のメンバーの装備も変えたいのに一回戻らなくてはいけない | そうびの画面（枠の一覧・候補の一覧）の上に「仲間の帯」を付けた。名前のタップ・◀▶・←→・Q／E キーで、戻らずに切り替わる。候補の一覧で切り替えると、同じ枠（例：武器）のまま、その仲間の候補と比較に変わる（選んでいた装備をその仲間も装備できれば、同じ装備にカーソル） |
| メニュー画面を心地よく使えるように | ステータス・じゅもん・とくぎにも同じ帯。ステータスから［そうびを変える］［じゅもん・とくぎ］でその仲間の画面へ直接行き、閉じるとステータスへ戻る。なかまの画面に［そうびを変える］。仲間を選ぶ一覧の最初のカーソルは、最後に見ていた仲間 |
| 道具画面の効果が表示される範囲が狭すぎるので上下に広げて | 効果の欄を、一覧と高さを分け合う形にした（一覧 11：効果 9）。下の表の「後」の値 |
| 道具の数によってウィンドウサイズが変わる。サイズは一律に | どうぐの窓の高さを、持ち物の数・分類・説明の長さによらず一定にした（そうびの候補・じゅもん・とくぎの窓も同じ） |

## 2. 変えたこと（詳しく）

- `js/ui/windows.js`：一覧（`Win.list`）に `opts.members`（仲間の帯）を足した。2 人以上のときだけ出す。タップ・◀▶・Q／E で `{ member, index }` を返す。`arrows` のときは ←→ でも（タブのない一覧だけ。タブのある一覧の ←→ は今までどおりタブ）。上に別の窓が開いている間は、下の帯は反応しない。パネル（`Win.panel`）に `opts.onPage`（Q／E）を足した（既存の `onKey` には渡さないので、クイズ・チャートバトルなどの画面の動きは変わらない）
- `js/core/engine.js`：Q＝前の仲間（prev）、E＝次の仲間（next）を入力の表に足した。Ctrl・⌘・Alt と一緒のとき（ブラウザの操作）は取らない。探索中は何もしない。PageUp／PageDown は割り当てていない（ページのスクロールを変えないため）
- `js/ui/menu.js`
  - そうび：枠の一覧・候補の一覧に帯。枠のカーソルは切り替えても同じ枠のまま。装備できるものがない枠は、以前は「装備できるものがない。」のメッセージで戻っていたが、押せない行と説明を出して、その画面から仲間を切り替えられるようにした。`Menu.equip(仲間)` で仲間を選ぶ一覧を飛ばせる
  - ステータス：帯（←→・Q／E・タップ）で切り替え。［そうびを変える］［じゅもん・とくぎ］［閉じる］・✕。Enter・Esc で閉じる（今までどおり）
  - じゅもん・とくぎ：帯（Q／E・タップ）。←→ は今までどおり分類のタブ。分類のタブは仲間を切り替えても同じ。特技のない仲間は、以前はメッセージで戻っていたが、「まだ覚えていない」の行を出して切り替えられるようにした
  - なかま：［そうびを変える］（戦闘メンバーのみ）。閉じると、なかまの画面へ戻る（そうびで切り替えた仲間を選んだまま）。Q／E でも仲間を切り替え。隊列の確認の小さい窓を開いている間は、後ろの一覧・タブ・ボタンを押しても動かないようにした（以前は後ろの一覧で別の仲間を選べてしまい、隊列の変更が別の仲間に効くおそれがあった）
  - 最後に見ていた仲間（`Menu._member`）は、この遊んでいる間だけ覚える。セーブには入れない
- `js/ui/mobile.js`：スマホの縦画面で、大きさが一律の窓（どうぐ・そうびの候補・じゅもん）・ステータス・なかまを開いている間、窓を置ける高さをゲーム画面の下の空き（操作パネルの上まで）へ広げる（`#ui` の高さだけ。キャンバス・3D の描画の大きさは変えない。resize の通知も出さない）。閉じると元に戻る。横画面・全画面のチャートの間は変えない
- `styles.css`：仲間の帯・大きさが一律の窓・広い効果の欄・スマホ（見出しのボタンを 1 行に、操作の説明を 1 行に、狭い画面では帯のレベルの字を隠す）・スマホ横画面（一覧を左、効果を右に並べる）

変えていないもの：セーブの形・LocalStorage のキー（3D `mtq-3d-slot-*`／2D `mtq-rpg-v2-slot-*`）・ストーリー・クエスト・キャラクター・職業・装備・アイテム・モンスター・呪文・特技・トレード機能。3D 版の読み込むファイルの並び（`3d/index.html` の script）は変わらないので、3D の作り直し（vite build）はしていない（版の印 `?v=` だけ更新）。

## 3. 大きさ（ヘッドレス Chromium で測った値。実機ではない）

どうぐの窓を 4 つの状態（持ち物 1 個／14 個／装備品を選んで詳細が長いとき／空の分類）で開き、窓・効果の欄の高さ（CSS の px）を測った。
変更前は `99a5685`（変更前の版）、変更後は作業中の版（2D・3D とも同じ値。3D は `docs/menu92/logs/menu92_3d_*.json`）。

| 画面 | 変更前：窓の高さ（4 つの状態） | 変更前：効果の欄 | 変更後：窓の高さ | 変更後：効果の欄 |
|---|---|---|---|---|
| PC 1920×1080 | 297／689／689／225（変わる） | 63／57／84／7 | **689（一定）** | **230（一定）** |
| PC 1280×720 | 297／499／499／225 | 63／38／54／7 | **499** | **144** |
| スマホ縦 390×844 | 337／466／466／278 | 63／29／52／7 | **600** | **174** |
| スマホ縦 360×800 | 401／431／431／342 | 63／20／33／7 | **559** | **155** |
| スマホ横 844×390 | 337／359／359／278 | 63／20／27／7 | **367** | **171**（右の列。一覧は左の列） |

- 変更前は持ち物が多いほど一覧が伸び、効果の欄が押しつぶされていた（スマホで 20px 前後＝1 行も入らない）。変更後は、窓も効果の欄も持ち物の数によらず同じ高さ
- 効果の欄に入りきらないとき（装備品の比較など）は、欄の中でスクロールする
- そうびの候補・じゅもん・とくぎの窓も同じく一律（仲間を切り替えても、PC 1920 で 689px のまま。`menu92_*.json` の equip・skills）
- スマホ縦画面は、窓を置ける高さをゲーム画面の下の空きまで広げた（360×800 で 468px → 608px。操作パネルの上 620px より上で止まり、パネルには重ならない）
- 変更前の測り方：`BEFORE=1` で同じ確かめ（`docs/tools/menu92/browser/menu92_browser.js`）を変更前の版に向けた（2D。3D は同じ CSS を読む）。記録 `docs/menu92/logs/before_2d_*.json`
