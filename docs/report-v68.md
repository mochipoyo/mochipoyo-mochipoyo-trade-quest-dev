# v6.8 報告：味方の戦闘用4方向の絵（主人公＋仲間14人）を3D版に組み込み

作業日：2026-11-02（開発用リポジトリ `feature/3d-full`。本番には未公開）

## 1. 依頼と対応

添付の `TradeQuest_Party_Directions_v3.zip`（15人×4方向＝60枚の 320×320 透過PNG）を、3D版の戦闘の味方の表示に組み込んだ。画像は作り直していない（パックの PNG をそのまま使用）。

| 場面 | 使う絵 |
|---|---|
| 前後の並び（ふだんの表示） | `back.png`（背中が手前） |
| 左右の並び（敵が左・味方が右） | `left.png`（敵がいる左を向く）。敵が右にいる並びなら `right.png`（今のゲームにはこの並びはない） |
| 勝利 | `front.png`（正面へ振り向く。読み込み済みのときだけ） |
| 開発の確認用 `?partydir=front\|back\|left\|right` | 指定した向きに固定（勝利の振り向きもしない） |

- **人物ID（`actor.id`）で選ぶ**：`hero, lina, kyle, mina, seris, gald, lucia, elna, nagi, iris, sophia, io, ganes, aster, ord`。職業（`actor.job`）・見た目のID（`actor.sprite`）・名前・並び順では選ばない。転職しても、旧セーブで `sprite` が別のIDになっていても本人の絵になる
- **選ぶ順**：同じ人物IDの職業別の絵（manifest の `actors[id].jobOutfits[job]`。今のパックにはないので、全職業で基本の絵）→ 同じ人物IDの基本の絵
- **転職の処理・セーブの形・2D版は変えていない**（`Actors.changeJob` はこれまでどおり `sprite` を書きかえるが、3D版の味方の絵はそれを見ない）
- ルシアはパックのとおり、紺の髪・青い衣装・青い杖の絵（コード上の職業 `waveblade`＝波形剣士から剣士の絵には描き変えていない）
- 新しく絵ができた8人（エルナ・ナギ・イーリス・ソフィア・イオ・ガネス・アステル・オルド）の外見は、パックの制作時に人物設定から作られたもの。以前のコードにその外見の設定があったわけではない

## 2. しくみ（`three-src/src/battle/PartyDirections.js`・`BattleActors3D.js`）

- **置き場所**：`assets/characters/party-directions-v3/sprites/<人物ID>/<向き>.png`（60枚）と `manifest.json`。原寸シート・プレビューはリポジトリに入れていない（ゲームでは使わない）。パックの説明・検査結果・取得元は `docs/party-directions-v3/`
- **URL**：2D版の `assets.js` の場所（`Assets.base`＝リポジトリの一番上。`3d/index.html` からでも同じ）＋ `assets/characters/party-directions-v3/` ＋ manifest の `path`。画像の URL には `?v=画像のハッシュの先頭10文字` を付ける（古い画像のキャッシュ対策。画像が変わったときだけ URL が変わる）。サービスワーカーはない
- **manifest**：3D版のビルド（vite）に取り込む（読み込みの通信が1回減り、manifest の読み込み失敗が起きない）。パックを差し替えたら `three-src` をビルドし直す
- **切り出しと足もと**：不透明な部分（透明度 >16。manifest の `opaqueBounds` と同じ基準。60枚すべて一致を確認）を切り出し、まわりに透明を2ドット足す。切り出したぶん、基準点 `pivot=[160,304]` の位置を補正して、足もとを立ち位置に合わせる
- **大きさ**：1ドットの大きさ＝ 基準の高さ × `worldHeightRatio` ÷ `referencePixelHeight`（同じ人物の4方向で同じ縮尺。主人公の元の絵が小さくても小さくならない）。基準の高さは、左右の並び 1.42（以前の立ち絵と同じ。既存の正面の絵がある7人は、以前とほぼ同じ大きさ）、前後の並び 1.2（以前の歩行のドット絵の後ろ姿は 0.95）
- **画質**：透過のまま。テクスチャは `NearestFilter`、切り出しは `imageSmoothingEnabled=false`。縦横比は元のまま。左右は描かれた `left.png`／`right.png` を使い、反転（`flipX`・負の拡大）はしていない。板（ArtVolume）はカメラの方を向く面に選んだ絵を貼る
- **先読み**：3D版の毎フレームの処理（1秒に1回）で、編成（人物ID）・職業・戦闘の並びが変わったときに、使う向き（back か left）と勝利の front を読み込む。戦闘の始まりでも同じものを読み込む（読み込み済みならそのまま）
- **キャッシュ**：画像の URL ごとに、Promise・画像・切り出したキャンバスを1回だけ作る。板（形とテクスチャ）は戦闘ごとに1人1回作る（毎フレームは作らない）
- **読み込み中と失敗を分ける**：読み込み中は最長 2.5 秒待つ（以前の絵の「4秒待ち」とは別。新しい絵が読めたらすぐ使う）。失敗（404・通信・CORS・読み取れない）は、人物ID・向き・URL・理由をコンソールと記録（`stats().failures`）に残し、2・4・8・15・30 秒の間隔で自動で読み直す（永久に失敗扱いにしない。`retry(url)` で今すぐ読み直すこともできる。戦闘の始まりでも読み直す）
- **失敗・遅いとき**：同じ本人の以前の絵（これまでの立ち絵・歩行のドット絵）で表示し、新しい絵が読めたら戦闘中でも差し替える。別の仲間の絵にはしない
- **演出**：被弾の点滅・のけぞり、倒れる・起き上がる、呪文の光、攻撃の踏み込み、勝利のジャンプ、行動と命中の時刻合わせは、以前の処理のまま（絵は静止画。動きのコマは作っていない）
- **カメラ合わせ・数字の位置**：味方の範囲（`homeBox`・`contentBox`・`partyPos`・`partyRect`）を、板の大きさではなく「足もと〜頭・武器の先」の見える範囲で計算する。勝利の振り向きでカメラが動かないよう、カメラ合わせは戦闘中の向きの絵で計算する

## 5. 確かめたこと・確かめていないこと

### 作業環境で確かめた（Playwright・Chromium のソフトウェア描画・`three-src/tools/test3d/p68_party.js`）

PC（1280×720）・iPhone 13 の縦（390×664）・横（664×390）の大きさで、すべて成功（横は B・E のみ）。

- **A 確認シート**：15人×4方向の60枚を、人物ID・向きどおりの URL（`/assets/characters/party-directions-v3/sprites/<ID>/<向き>.png?v=…`）で読み込み、切り出し範囲が manifest の `opaqueBounds` と60枚すべて一致。画像の取り違え・正面と背面の取り違えがないことを目で確認
- **B 4人編成×前後／左右**：15人を4組（主人公は2組）。前後＝全員が本人の `back.png`、左右＝全員が本人の `left.png`。オート戦闘で攻撃・呪文・被弾を経て勝利し、生きている全員が本人の `front.png` に振り向く
- **C 転職・旧セーブ**：主人公・カイル・エルナ・イオを転職させても、転職前と同じ本人の絵（`Actors.changeJob` で sprite が `hero_mage` などに変わっても）。sprite を別のID（カイル＝`hero_knight`、イオ＝`kyle`、エルナ＝`villager_m`、主人公＝`hero_sage`）にしたデータでも本人の絵。普段のセーブ枠には書き込んでいない（`State.data` に直接入れた）
- **D 失敗と復帰**：リーナの `back.png` を 404 にすると、リーナは以前の絵（歩行のドット絵の後ろ姿）で表示し、人物ID・向き・URL・理由がコンソールと記録に残る。404 をやめると自動の読み直しで本人の `back.png` に差し替わる。ミナの `back.png` を5秒遅らせると、2.5秒で以前の絵で始め、読めたら差し替わる
- **E 死亡・蘇生・再戦**：倒れた仲間は本人の絵のまま倒れて表示され（消えない）、蘇生で同じ絵のまま起き上がる。再戦で味方の板が4人ぶんだけ（前の戦闘の板が残らない）
- **F 別のサイトから読む**（githack の配信の再現）：CORS を許可するサイトからは4人とも新しい絵を3Dで使える。許可しないサイトでは新しい絵は使えず、4人とも以前の絵で表示（エラーで止まらない）
- ネットワーク：わざと 404 にしたもの以外に、`party-directions-v3` の 404 などはなし。ページのエラーなし（わざと起こした 404・CORS の失敗のログを除く）
- **行動と命中の時刻合わせ**：処理は変えていない。同じテスト（オート戦闘・PC の大きさ）で、変更前の版（コミット 1070fcd）と命中の時刻のずれを比べた。中央値は、変更前が前後の並び 約150ms・左右 約190〜260ms、変更後が前後 約180〜190ms・左右 約230〜270ms（同じ程度だが、変更後が少し大きい。作業環境はソフトウェア描画で1秒あたりのコマ数が少なく、ずれが大きく出る。新しい絵はテクスチャが大きいぶん描画が少し重い可能性がある。実機での時刻合わせは未確認）
