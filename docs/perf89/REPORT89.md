# v8.9 スマホの移動の重さ（カクカク）対策 — 報告

対象ブランチ：`feature/perf-mobile-20261109`（`feature/ux-gameplay-20261109` の 358ff60 から）。main・本番へは出していません。

## 1. 調べ方（この環境でできること・できないこと）

- 実機（スマホ）はこの環境にありません。**実機での fps・なめらかさは測っていません（未検証）**。
- 代わりに、ヘッドレス Chromium でスマホの画面（390×844・DPR 3・タッチ）を再現し、CDP で **CPU を 4 倍遅く**して（スマホの CPU の目安）測りました。
- 描画は GPU の代わりのソフトウェア描画（SwiftShader）なので、**GPU の重さ（画面を塗る時間）は測れません**。GPU については「描画の回数・三角形の数・影を描く範囲」など、端末によらない数で比べました。
- 改善前（358ff60）と改善後を、同じ手順・同じ条件で、1 つずつ順番に測りました（同時に動かすと CPU を取り合うため）。この環境は CPU を共有しており、同じ計測でも ±30% 程度ぶれます。

計測の道具（すべて `docs/tools/v89/`）：

| 道具 | 測るもの |
|---|---|
| `browser/perf89.js` | 描画の回数（影の分を分けて）・影を落とす物・毎コマの処理の時間（描画を除く）と内訳・描画の命令を作る CPU の時間 |
| `browser/perf89rt.js` | 実時間で 40 秒歩いたときのコマの間隔・長い処理（50ms 以上）の数 |
| `browser/join89.js` | となりの地域（つながった世界）を裏で組み立てるときの、いちばん長い 1 回の止まり |
| `browser/shots89.js` | 見た目の比べ（同じ場所・時刻・カメラ） |
| `browser/mut89.js` | 歩いている間に毎コマ書き換わっている画面の部品 |
| `profsum89.js` / `profwin89.js` | CPU プロファイルのまとめ（どの関数が時間を使ったか・止まった区間の中身） |
| `logic89_test.js` | 軽くした処理の結果が以前と同じか（jsdom） |
| `smooth89_test.mjs` | なめらかさ優先（解像度の自動調整）の決まり |

## 2. 分かった原因（改善前 358ff60・スマホ相当）

| # | 原因 | どこで | 根拠（測った数） |
|---|---|---|---|
| 1 | **影の描画が画面の描画より多い**。主人公を中心に 44×44 マスの範囲で、画面の外（後ろ・横）の家・木・人・動物まで毎コマ影を描いていた | 3D・町／フィールド | ポヨ村：1 コマの描画 384 回のうち影が 276 回（画面は 108 回）。リヴェル城下町 425 回中 258 回、トレーディア 459 回中 281 回 |
| 2 | **動物 1 匹が 10 個ほどの部品**で、部品ごとに影を描いていた（足元の丸い影もあるのに） | 3D・町 | ポヨ村で影を落とす物 240 個のうち 124 個が動物の部品 |
| 3 | **クイズモンスターのいるフィールドで、マスが通れるかを調べるたびに 55 体分の記録を全部確かめ直していた**（`QuizSymbol.list` → `Quiz.ensure`）。3D の当たり判定・2D の移動で毎コマ何度も呼ばれる | 2D・3D 共通 | `map.passable` 1 回：フィールド「world」で 約 85µs（この環境）。CPU プロファイルで、フィールドを歩く間の CPU の約 19% |
| 4 | **フィールドの最初の 1 歩で、入口のまわりの計算**（`World.landmarkFoot`）が走る | 2D・3D 共通 | 全フィールドの合計 約 136ms（この環境・1 倍）。スマホ相当（4 倍遅く）で最初の 1 歩が 45〜64ms 止まる |
| 5 | **町で 1 歩ごとに、次の目的地への道を調べ直していた**（`Nav` の道探しで、マス 1 つごとに出来事の一覧を 2 回なめる） | 2D・3D 共通 | ポヨ村で 1 歩 約 0.6ms（この環境）。スマホ相当で 1 歩ごとに 6〜10ms |
| 6 | **毎コマ、画面の文字を書き直していた**（ミニマップの見出し・スマホの「全画面」ボタン）。そのたびに画面全体の配置の計算がやり直しになり、3D 側の位置合わせで毎コマ強制的に計算 | 2D・3D 共通（スマホ） | 歩いている 120 コマで、2 つの部品が 120 回ずつ書き換わっていた（`mut89.js`）。3D の位置合わせ（ui.layout）が 1 コマ平均 0.6〜0.8ms（4 倍遅く） |
| 7 | **ポヨ村の屋内 19 部屋を、世界のどこにいても始めてすぐ続けて作っていた**（区切りなし） | 3D | 実時間でフィールドを歩く確かめで、長い処理（50ms 以上）が 40 秒で 26 回・最長 8.5 秒・合計 11.4 秒（4 倍遅く） |
| 8 | **となりの地域（つながった世界）を裏で組み立てるとき、1 回の区切りが長い**（飾りの形を 1 つずつ作り直す・地形の計算をまとめて行う） | 3D・フィールド | 1 回の止まりの最長：グラニア 294ms・カリオン 172ms・諸島 234ms（4 倍遅く） |

ほかに気づいたこと（対策していない・影響は小さいと判断）：
- 夜・屋内では街灯の点光源 4 つ（軽量）を毎コマ近い順に並べ替えている（小さい）。
- 主人公・人の体（1 人 約 6,300 三角形）が三角形の数の大半。形を軽くするには素材（モデル）を作り直す必要があり、今回は手を付けていません。
