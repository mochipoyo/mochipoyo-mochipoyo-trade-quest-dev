# v8.9 スマホの移動の重さ（カクカク）対策 — 報告

対象ブランチ：`feature/perf-mobile-20261109`（`feature/ux-gameplay-20261109` の 358ff60 から）。main・本番へは出していません。

## 1. 調べ方（この環境でできること・できないこと）

- 実機（スマホ）はこの環境にありません。**実機での fps・なめらかさは測っていません（未検証）**。
- 代わりに、ヘッドレス Chromium でスマホの画面（390×844・DPR 3・タッチ）を再現し、CDP で **CPU を 4 倍遅く**して（スマホの CPU の目安）測りました。
- 描画は GPU の代わりのソフトウェア描画（SwiftShader）なので、**GPU の重さ（画面を塗る時間）は測れません**。GPU については「描画の回数・三角形の数・影を描く範囲」など、端末によらない数で比べました。
- 改善前（358ff60）と改善後を、同じ手順・同じ条件で、1 つずつ順番に測りました（同時に動かすと CPU を取り合うため）。この環境は CPU を共有しており、同じ計測でも ±30% 程度ぶれます。

計測の道具（すべて `docs/tools/v89/`）：

## 6. 確認済み・推測・未確認

**確認済み（この環境で測った・試した）**
- 影の描画の回数が町で 3〜6 割減った（ポヨ村 59%・リヴェル城下町 31%・トレーディア 40%）。画面に映る物の描画の回数は変わらない。
- 毎コマの処理（描画以外）が、スマホ相当の CPU で 2〜6 割減った（24〜64%）。フィールドの最初の 1 歩の止まりが大きく減った（はじまりの草原 64.9 → 14.3ms、マギカ 53.7 → 26.3ms）。
- 実時間で歩いたとき、長い止まり（50ms 以上）の合計がフィールドで 11.4 秒 → 1.7 秒、ポヨ村で 0.3 秒 → 0 秒。
- となりの地域の組み立ての、いちばん長い止まりが 3〜4 割短くなった。
- 2D 版・3D 版の既存のテストの結果は変わらない（変更前からの NG 2 件は同じ）。セーブのキーは混同していない。

**推測（測っていない）**
- 実機のスマホでも、影の描画が減ったぶん GPU と CPU の仕事が減り、カクカクは減ると考えますが、どのくらい fps が上がるかは端末によります。
- 画面を塗る仕事（GPU）が重い端末では「なめらかさ優先」が解像度を下げて助けるはずですが、実機では試していません。CPU が重い端末・省電力で 30 コマに固定されている端末では、1 回試して効かなければ元に戻す作りです。

**未確認・未対応**
- **実機（スマホ）での fps・カクカクの体感は確かめていません。** 目標（スマホ 30fps）に届いたかは分かりません。
- 実機の GPU の時間（画面を塗る時間）は測っていません。
- iPhone（Safari）・Android（Chrome）のどちらでも試していません。
- となりの地域の組み立てで、まだ 1 回 110〜170ms（スマホ相当）の止まりが残っています（地形・飾りをまとめて作る所）。地図の切り替え（建物の出入り）の読み込みも同じくらい止まります（読み込みの画面が出る所）。
- 人の体の三角形の数（1 人 約 6,300）は減らしていません（素材の作り直しが必要）。
- 夜の街灯の点光源（軽量で 4 つ）はそのままです（減らすと見た目が変わり、切り替えのたびにシェーダーの作り直しで止まるため）。
