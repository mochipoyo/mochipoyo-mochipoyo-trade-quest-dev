## 4. 対応できなかった場所・画像と理由
1. **3D版の戦闘**：前後の並び（既定）は画面いっぱいの画像に差し替え済み（3Dの地面・景色を隠す方式）。左右の並びは遠景の板だけです。画像は1枚の絵なので、カメラが動いても背景は動きません（3Dの景色のような奥行きは出ません）。
2. **山岳の差分**：確実にわかる2つのダンジョンだけ。フィールドの山のふもとなどは、場所の判定から山かどうかがわからないため使っていません。
3. **sea・sky の画像**：素材の注記どおり低解像度起源（一覧画像の切り出し）です。PC の画面ではやや甘く見えます。作り直しは素材側の作業です。
4. **地域ごとの画像**：画像は14種で地域別ではないため、地域の色は薄い色の重ね合わせで近づけているだけです。

## 6. その他の追加のご依頼

### 「元気にロード中...」
建物に入ったときなどの「3Dの村を組み立てています...」を含む、3Dの読み込み中の文をすべて「元気にロード中...」にしました。

### メニューの透明度
ゲーム画面の上に出す窓（メニュー・会話・戦闘のコマンドと味方の欄）の背景を、不透明度 .97 → .87 にしました（**約10%透けるように**）。
- 解釈について：「透明度を下げる」は「不透明にする」とも読めますが、もとの不透明度が .97 で、10%不透明にする余地がないため、「透けるように」と解釈しました。逆の意味でしたら、すぐ戻せます（`styles.css` の1行）。

### 敵のHPバー
- 初期値は**表示しない**。設定（メニュー → 設定）の「敵のHPバー」で 表示する／表示しない を切り替え（すぐ反映・セーブに保存）。
- 以前のセーブ（設定の項目がない）は「表示しない」になります。
- 対象を選ぶ一覧の HP の数字は、従来どおり出ます（バーだけを消しています）。
- 確認（`p2_hpbar`・2D版）：設定なし（以前のセーブと同じ）→ バーの色の画素 0、「表示する」→ 1180、「表示しない」→ 0。設定の一覧に項目あり。3D版の戦闘も同じ描画処理です（3D版での画面の確認は未実施）。

### 夜のフィールドが暗すぎる → 調整
- 3D版の夜の値：月明かり 0.35 → 0.72、空の明かり 0.35 → 0.66（色も明るい青に）、露出 1.05 → 1.16、霧の濃さ（夜の上乗せ）0.010 → 0.004、空・霧の色を明るく。夕方の明かりも少し上げました。
- 比較：`docs/3d/images/v66/night_before_after.jpg`（同じ場所・同じ時刻。以前はほぼ真っ黒 → 地形・道・木が見える）。
- 2D版の夜（画面に重ねる青い色。最大 50%）は変えていません。2D版も暗いと感じる場合はお知らせください。

### 夜の村や町で街灯がチラチラする → 調整
- **原因**：街灯の光（点光源 4〜8 個）を、毎フレーム「主人公に近い順」に付け替えていました。歩いて順位が入れ替わると、街灯の明かりが一瞬で点いたり消えたりしていました。
- **修正**：照らしている街灯を保持し、近い順の「個数＋2」から外れたときだけ 0.35 秒かけて消し、空いた光で新しい街灯を 0.35 秒かけて点けます。あわせて、月（太陽）の影の範囲を影の画素単位で動かし、歩くたびに影のふちがチラつくのを抑えました。
- 測定（`p2_lampflicker`、リヴェル城下町の夜を4〜9秒歩く。ソフトウェア描画で1フレームが約 0.5 秒と非常に遅い条件）：

| | 1フレームでの街灯の明かりの最大の変化 | 急な変化（50%超）の回数 |
|---|---|---|
| 以前 | 100%（一瞬で点く・消える） | 8回 |
| 今回 | 41%（この遅い条件での上限） | 0回 |

  実機（60fps）なら1フレームの変化は数%になる計算ですが、**実機では未確認**です。

## 8. 更新が必ず届くようにする（12:21 のご依頼）
- **原因**：ゲームの JS（`js/…`）・`styles.css` は、いつも同じ URL（ファイル名）で読んでいたため、ブラウザや配信元（githack は数分、GitHub Pages も数分程度）が前の版を使い続けることがありました。12:18 のスクショは、押し上げ（12:13）の直後で、前の版（敵のHPバーが出ている）が表示されていたと考えられます（推測。手元では再現できません）。
- **対策1：ファイルごとの版の番号**：`index.html`・`3d/index.html` が読むファイル（JS 142・CSS 1）の URL に「`?v=中身のハッシュ`」を付けました。中身が変わったファイルだけ URL が変わるので、ページ（HTML）が新しくなれば、前の版の JS が使われることはありません。3D版の本体（`3d/assets/main-…js`）は、もとから名前にハッシュが付いています。
  - 付け直しは `node tools/stamp-version.js`（ビルドのあと・コミットの前に実行）。`--check` で付け直し忘れを確認できます（忘れていれば終了コード 1）。
- **対策2：新しい版のお知らせ**（`js/core/update-check.js`）：開いて 15 秒後・10 分ごと・画面に戻ったときに、公開中の版（`version.json`・キャッシュを使わずに取る）と、読み込んだ版（`js/core/version.js`）を比べ、違えば画面の上に「新しい版があります［更新する］［×］」を出します。
  - ［更新する］：戦闘・会話中は「終わってから押してください」と出して何もしない。探索中は自動セーブしてから読み込み直す（URL に `?_v=版` を付けて、前のページを使わないようにする）。
  - 通信できないときは何も出しません。
- **限界**：ページ（HTML）そのものは、配信元が数分キャッシュすることがあり、押し上げの直後は前の版が開くことがあります（配信元の設定のため、こちらでは消せません）。その場合も、新しい版が公開済みなら上のお知らせが出ます。画像（`assets/…`）には版の番号を付けていません（同じ名前の画像を差し替えることがないため）。
- 確認（この環境）：2D版・3D版とも JS 142 本すべて `?v=` つきで読み込み。版が同じならお知らせなし、違えばお知らせ。戦闘中の［更新する］は読み込み直さない。探索中は自動セーブ（スロット0）して `?_v=` つきで読み込み直す。**実際の配信元（githack・GitHub Pages）での確認は未実施**。
