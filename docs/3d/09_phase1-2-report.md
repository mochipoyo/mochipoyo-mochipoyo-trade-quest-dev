# Phase 1・Phase 2 の報告（本格フル3D化プロジェクト）

ブランチ：`feature/3d-full`（作業用リポジトリ）　**本番（GitHub main）には反映していません。**
画面の確認はすべてソフトウェア描画（GPU なし）です。fps は実機の値ではありません。

## 1. 実装した機能

### Phase 1：汎用3Dワールド基盤（ポヨ村以外のすべてのマップ）

#### WorldBuilder3D（`src/world/WorldBuilder3D.js`）
2D版のタイルから、町・フィールド・ダンジョン・屋内を自動で3Dにします。
- **地面**：区画ごとの格子。高さはタイルの種類から決め、水辺は低く、丘・山は高くします。足もとの高さは `heightAt()` 1か所で決めます。
- **塗り分け**：2枚のデータテクスチャ（石畳・土・岩・平滑の割合と、色）で塗り分けます。
- **水・溶岩・雲海**：揺らぎのある面を1枚ずつ。橋・桟橋の下は水にします。
- **壁・崖・洞窟の壁**：材質ごとに結合します。部屋の手前（南）の壁は低くして、中が見えるようにします。
- **山**：手続き型の形を GPU インスタンスで描きます。地域によっては雪をかぶります。
- **木**：1つの BatchedMesh に入れ、木ごとに LOD を切り替えます（主人公の近くだけ精細）。
- **小物**：タイル約40種を、Blender のモデルに対応づけています。
- **その他**：ワールドマップの目印（村・城・洞窟・塔）、ダンジョンのたいまつと明かり、屋内の天井の明かり。

#### 地域テーマ（`src/world/themes.js`）
- 2D版の戦闘背景と同じ地域12・場所14を使います。
- 地域ごとに、木の種類（ヤシ・枯れ木・雪の針葉樹）、色、霧、暗さ、壁の材質を変えます。

#### 状態の管理（`src/world/coverage.js`）
- 旧 `MAPS_3D`（ポヨ村だけ）を置き換え、マップごとに `done` / `generic` / `2d` を返します。
- 3D設定に「3Dの範囲：全マップ／ポヨ村だけ」を追加しました。

#### 移動と出来事（2D版のロジックをそのまま使用）
- 自由移動でマスをまたぐと、2D版の `World.onStep` を呼びます。出入口・出来事・歩数・エンカウントは2D版と同じです。
- 進めない方向へ押し続けたときは、2D版の `World.tryMove` に任せます。外周からの退出・乗船・アストラ号・ボスやクイズのシンボル・NPC に道をあけてもらう、が対象です。
- 当たり判定に、ボスとクイズモンスターのシンボルを追加しました（2D版の `passable` と同じ）。
- **乗り物**：乗っているあいだは2D版と同じマス単位の移動（gridMode）です。3D側は位置を写して、船・飛空艇の3Dモデル（仮）を描きます。

#### 建物（BuildingBuilder3D）
- 地域の色を反映します。
- 城（type castle）は、石の外壁・四隅の塔・胸壁・門で作ります（仮の形）。

#### メモリと読み込み
- 汎用3Dのマップは直近の3枚だけを保持します。
- Phase 1〜2 で追加したモデルは、使うときに読み込みます（lazy）。

### Phase 2：3Dの戦闘（ご指示により、添付の構図に変更）

#### 構図
- 左に敵、右に主人公たち、奥に3Dの景色。斜め前の少し上から見ます。
- カメラの距離は画面の縦横比から決めるので、スマホの縦画面でも全員が入ります。

#### 敵（`src/battle/ArtVolume.js`）
- 2D版の敵の絵（新しい画像・ボス画像・従来の絵）を**そのまま**使います。
- 輪郭から、内側ほど厚くふくらむ立体（2.5D）を自動で作ります。
- 光・地面の影・揺れを付けます。被弾は白く光って後ろへ、撃破と登場は溶けるように消えて現れます。
- 正面から見たデザインは元の絵と同じです。
- 敵の数（2〜4体）ごとに並びを決めています。遠近で手前と奥の敵が画面上の同じ位置に重ならないよう、手前・奥で横位置が交互になるようにしました。

#### 味方（ご指示により、参考画像のとおりドット絵のまま並べる方式に変更）
- 2D版の戦闘のパーティ欄と同じ立ち絵（ドット絵）を、ごく薄い板にして右に前後2列で互い違いに並べます。
  - 人数（1〜4人）ごとに並びを決め、隣どうしがほとんど重ならない間隔にしました（4人でも全員が見えることを画面で確認）。
  - ドットはぼかしません。光と地面の影は付きます。
  - 絵の探し方はパーティ欄と同じ順です：本人の立ち絵 → 見た目（スプライト）の立ち絵 → 歩行のドット絵（左向き）。
  - 例：主人公が時魔導士のときは、パーティ欄と同じ「僧侶の見た目の立ち絵」になります。
- 動き：打撃は相手の手前まで跳んで斬り、命中の瞬間に前へ傾いて戻ります。ほかに、呪文の光・被弾の白い光とのけぞり・倒れる（横になる・暗くなる）・勝利のジャンプ・防御があります。
- 味方はドット絵に固定しています（実機テストで3Dモデルが出たため、3D設定の切り替えを外しました。3Dモデルは開発の確認用に URL の `?party=model` でだけ出せます）。

#### 同期
| 2D版の出来事 | 3Dの動き |
|---|---|
| 行動の演出の開始（FX65 'play'） | 行動する人の動き。命中の瞬間が2D版の時刻表の命中時刻に重なるよう、開始を遅らせるか速めます |
| 命中（hitflash・ダメージの数字） | 当たった人ののけぞり |
| 倒れる（die／HP 0） | 撃破の演出 |
| 勝利 | 勝利のポーズ |

- 計算（`combat.js`）とバランスは変えていません。

#### 実機のテストプレイ（iPhone・2026-11-02）で見つかった問題と対応
- **報告**：iPhone で戦闘が以前の2Dの表示のままだった（画面写真あり）。
- **確認できている事実**：以前のコードでは、3Dの戦闘は「3Dの素材（GLB 47個・約4.7MB、テクスチャ 19枚・約2.2MB）の読み込みがすべて終わってから」使えるようになっていた。読み込み中や、読み込みが終わらないとき、3Dの初期化に失敗したときは、戦闘は2Dの表示になる。何も知らせずに2Dになっていた。
- **原因**：上のどれに当たったかは**未確認**（この作業環境から実機の様子は見えない）。
- **対応**：
  - 戦闘の3D（敵＝絵の立体、味方＝ドット絵）は GLB を使わないので、素材の読み込みを待たずに使えるようにした（WebGL が使えるようになった時点で準備）。
  - 3Dの戦闘が使えずに2Dになったときは、理由を画面の下に6秒表示する（例：「3Dの戦闘を表示できないため、2Dで表示しています（WebGL の文脈が失われた…）」）。3D全体が使えないときも理由を表示する。
  - WebGL の文脈が失われた・例外が出たときは、その戦闘は2Dのまま、次の戦闘で作り直す（1回の起動で3回まで）。
  - 3D設定に「状態」を追加：3Dの準備・戦闘の表示・WebGL・GPU・画質・**版（ビルドの日時）**。古い版が表示されていないかも確かめられる。
- **この環境での確認**（`p2_robust`。スマホの画面サイズ・ソフトウェア描画）：
  - GLB の読み込みを90秒遅らせても、最初の戦闘から3D（左右に並ぶ表示）になる。
  - 文脈を失わせると、その戦闘は2Dと理由の表示、次の戦闘で3Dに戻る。
  - 戦闘の組み立てで例外を出すと、2Dと理由の表示、次の戦闘で3Dに戻る。
  - 以前のテスト（歩く・出入り・乗船 9/9、セーブ 4/4、スマホのタップで戦闘、PC の位置）も変わらない。

#### 実機のテストプレイ 2回目（iPhone・2026-11-02 朝）で見つかった問題と対応
- **報告**：村やフィールドは3Dになった。戦闘の味方がドット絵ではなく3Dモデルだった。味方が全員 HP 0 のまま、戦闘が「〜が現れた！」から進まない（画面写真あり）。
- **戦闘が進まない件：この環境で同じ状態を再現できた**（`p2_wipesave`。2D版のページでも同じ。既存の不具合で、公開中の2D版にもあると考えられる）
  1. 全滅すると、戦闘の終わり（`js/ui/battle.js`）で自動セーブされる。このとき味方は全員倒れたまま。宿で回復するのは、その後のメッセージ（「全滅してしまった……」）を閉じてから。
  2. そのメッセージの間にページが読み込み直されると（スマホのブラウザがタブを読み込み直す・閉じる など）、「つづきから」で全員 HP 0 のまま始まる。
  3. 次の戦闘で、敵の行動の計算（`combat.js`）が「倒れていない味方」がいないため例外になり、戦闘が止まる（画面は「〜が現れた！」のまま）。
  - 実機で実際にこの順序だったかは**推測**（HP・MP の値と画面は一致）。
- **修正**（`js/ui/battle.js`。`combat.js` の計算とバランスは変えていない）：
  - 全滅のときは、戦闘の終わりで自動セーブしない（宿で回復したあとに保存される）。
  - 味方が全員倒れたまま戦闘が始まったら、戦わずに全滅として扱う（宿へ戻って回復。所持金の半分を失うのは通常の全滅と同じ）。すでに全員 HP 0 で保存されたセーブも、次の戦闘で元に戻る。
  - 戦闘の途中で例外が起きても止まったままにせず、戦闘を終える（味方が残っていれば逃げたのと同じ、全員倒れていれば全滅）。画面の下に「戦闘の処理でエラーが起きたため、戦闘を終えました」と表示。
- **味方が3Dモデルだった件**：3Dモデルが出るのは、3D設定の「戦闘の味方」で「3Dモデル」が選ばれたときだけ。テストのとき（「状態」を見ていただいたとき）に押された可能性がある（**推測**）。ご指示どおりドット絵に固定し、設定の項目を外した。
- **この環境での確認**：
  - 全滅のメッセージの間に読み込み直しても、セーブは戦闘の前の状態（2D版・3D版とも）。
  - 全員倒れたままの戦闘は全滅として扱われ、宿で回復（2D版・3D版とも）。
  - 例外のときは戦闘を終えて探索に戻る（2D版・3D版とも）。
  - 以前の3D設定の値（3Dモデル）が残っていても、味方はドット絵（立ち絵）。
  - スマホのタップで戦闘を最後まで、味方の絵の種類（4人とも立ち絵）も変わらない。

#### 実機のテストプレイ 3回目（iPhone・2026-11-02 朝）で見つかった問題と対応
1. **3Dの戦闘を表示できない**（画面の下に「3Dの戦闘の表示に失敗（The operation is insecure.）」）
   - **原因（この環境で再現・確認済み）**：iPhone の Safari では、2D版の画像（立ち絵・敵の絵）が「別のサイト扱い」になり、3Dで使うために絵を読み取ると Safari が禁止していた。味方のドット絵の切り出しは例外を受け止めておらず、戦闘全体が2Dに戻っていた（敵の絵は受け止めていたため、敵だけ2Dの絵になっていた。2回目の写真で敵が中央にいたのはこのため）。
     - この環境で同じ条件（画像を別のサイトから読む）を作ると、以前の版は同じ例外（Chrome では「The canvas has been tainted by cross-origin data」）で2Dに戻り、修正版では3Dのまま最後まで戦闘できた（`p2_taint`）。
     - 画像が「別のサイト扱い」になる理由（githack の配信のしかた・Safari の扱い）は**未確認**。
   - **修正**：3Dで使う画像が読み取れないときは、同じ画像を CORS（`crossOrigin`）で読み直してから使う（`src/battle/readable.js`）。読み直せないときは、その敵だけ2Dの絵・味方は2D版の簡易ドットで代用し、戦闘は止めない。遠景の板・探索中のボスのシンボルも同じ（読めなければ板なし・光の輪だけ）。
     - 確認：CORS を許可するサイトからの画像 → 6枚を読み直し、敵・味方とも3D（味方は立ち絵）。許可しないサイト → 味方は簡易ドット、戦闘は3Dのまま。ボスのシンボルのあるマップも3Dのまま。
   - 3Dが2Dに戻ったときの理由に、例外の種類と段階（組み立て・動き・描画）を足した。マップの3Dに失敗したときも理由を表示し、3D設定の「状態」に出す。
2. **2D表示にすると3D設定のボタンが消える**
   - **原因**：3D設定のボタンは、3Dのマップを表示しているときだけ出していた。
   - **修正**：2Dのマップでも、探索中は「3D設定」を出す（ズームの＋－は出さない。戦闘・会話中は出さない）。2Dのマップから「3Dの範囲」を全マップに戻せることを確認（`p2_tools2d`）。
   - 補足：フィールドが2Dになったのが設定によるものか、上の画像の問題（ボスのシンボルの絵）による自動の切り替えかは**未確認**。後者は修正済み。
3. **スマホでミニマップ（画面の上）が切れる**
   - この環境（スマホの画面サイズの再現）では、ページの高さは画面と同じで、ずれは起きない（`p2_scroll`）。実機で何が起きているかは**未確認**。写真からは、ページ全体が約50px 下へずれている、またはアドレスバーの下に重なっていると推測。
   - **対策**（`js/ui/mobile.js`。スマホの表示のときだけ）：ページが縦にずれたら一番上へ戻す（文字の入力中は除く）。画面の大きさは、実際に見えている高さ（`visualViewport`）に合わせ、ツールバーの出し入れでも合わせ直す。
   - 3D設定の「状態」に、画面の大きさ・見えている範囲・スクロールの量を出すようにした。直らないときは、この値で原因を絞れる。
- **回帰テスト**：2D版の一式 52本のうち 51本が合格。fx65test の1項目（数字が出る時刻のずれ 79ms＞基準 60ms）が NG だったが、別の重いテストを同時に動かしていた時間帯。単独で2回実行し直して 25/25 合格。歩く 9/9・セーブ 4/4・PC の位置・スマホのタップで戦闘・2D版の画面も変わらない。

#### 実機のテストプレイ 4回目（iPhone・2026-11-02 朝）で見つかった問題と対応
1. **全体マップを開くと、3D設定のボタンとマップのボタン（＋・－・現在地・全体）が重なって押せない**
   - **原因**：3D設定のボタン（＋・－・3D設定）を、3Dのマップを表示している間はいつも出していた（全体マップを開いても出たまま）。
   - **修正**：3D設定のボタンは、探索中で、全体マップ・メニュー・会話を開いていないときだけ出す（PC でも同じ）。
   - 確認（`p2_mapbtn`）：全体マップを開くと3D設定は消え、マップのボタン8個はすべて押せる（3Dのマップ・2Dのマップとも）。閉じると戻る。
2. **画面全体が拡大されて元に戻らない**
   - **原因**：実機でどの操作から拡大されたかは**未確認**。iPhone の Safari では `user-scalable=no` が効かず、2本指の操作（全体マップの上など）や、文字が 16px より小さい入力欄を押したときに画面全体が拡大されることがある。拡大されると、ゲームがページの移動を止めているため戻しにくい（推測）。3回目に入れた「ページがずれたら戻す」「見えている高さに合わせる」も、拡大中は邪魔になり得たため止めた。
   - **修正**（`js/ui/mobile.js`・`styles.css`。スマホの表示のときだけ）：
     - Safari の画面全体の拡大（gesturestart など）を止める。ゲームの中の2本指の操作（全体マップの拡大・3Dのズーム）はそれぞれの画面が受け取るので使える。
     - ダブルタップでの拡大を止める（`touch-action: manipulation`）。
     - 入力欄の文字を 16px にする（押したときの自動拡大を防ぐ）。
     - それでも拡大されたままになったら、viewport の指定を一度書き換えて等倍に戻す。拡大中は「ページのずれを戻す」「画面の大きさを合わせ直す」をしない。
   - 確認：拡大の合図が止まること、入力欄が 16px であること。拡大させた状態（Chromium の再現）から、戻す処理で等倍に戻ること（書き換えを止めた比較では拡大のまま）。**iPhone の Safari での効き目は未確認**。
